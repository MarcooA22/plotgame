# PlotGame Governance

PlotGame is currently an early project. Governance should be clear enough to coordinate contributions without creating unnecessary bureaucracy.

## Current model

**Project Lead / Product Direction: Marco Amado**

The project lead currently makes final calls on:

- core product direction
- major roadmap changes
- major gameplay rules
- ambiguous contribution decisions
- maintainer access
- moderation policy
- conflicts that cannot be resolved through normal review

## Maintainers

If contribution volume grows, maintainers can be added for specific areas such as:

- gameplay / engine
- UI / UX
- infrastructure
- translations
- community / moderation
- educational / mathematical review

Maintainer roles should reflect real recurring responsibility, not honorary titles.

## Decision principles

Prefer:

- clear player value
- mathematical coherence
- fun and replayability
- accessibility
- simplicity over unnecessary complexity
- transparent reasoning
- changes that can be tested

Avoid:

- features added only because they are technically impressive
- opaque decisions
- merging changes nobody can maintain
- inflating project claims beyond what has actually been built or validated

## AI-assisted review

AI may help triage Issues and Pull Requests, summarize changes, identify regressions, and flag unclear or risky contributions.

AI does not have final authority.

Ambiguous product or community decisions escalate to human maintainers.

## Evolution

This governance model should become more formal only if real participation creates a need for it.
